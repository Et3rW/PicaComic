# 5.1.6 正式发布说明

本版本发布 nhentai **点标签叠加**，并汇总 5.1.6 测试版第 1、2 版的反馈。第 1 版提供了单独的“组合标签搜索”页面，用户试用后希望改为在浏览中叠加标签，第 2 版按此重做，经用户实际使用确认后发布。版本号统一为 5.1.6（5016）。

## 功能

- **点标签叠加**：在 nhentai 的分类页或标签页里打开漫画，再点漫画里的标签，会打开“页面原有标签 + 新标签”的页面，例如“中文 + glasses”。排版和原来的分类页一样，可以切换排序、翻页。
- **标签卡片**：标题栏显示当前所有标签，每个都带 ×，点一下就去掉这个标签，页面原地刷新；只剩一个标签时不显示 ×。在叠加页里打开漫画、再点标签，可以继续叠加，最多 5 个。
- **叠加规则**：
  - 新点的语言会替换掉原来的语言；`translated`、`rewrite` 等不是语言本身，照常叠加；
  - 已经在组合里的标签不会重复添加；
  - 从首页、收藏、历史、关键词搜索打开的漫画，点标签仍然只搜这一个标签。
- **设置 → 漫画源 → nhentai**：
  - “点标签时叠加到当前标签”开关，默认打开，关掉后和 5.1.5 的行为完全一样；
  - “默认排除的标签”：在这里加的标签，会在所有 nhentai 关键词搜索、分类页和叠加页里自动排除；搜索里手写了的标签，以手写的为准；搜索历史里记的仍是用户自己输入的关键词。
- **修复**：漫画详情页点“角色”里的标签，原来会退化成普通关键词搜索，现在改成打开角色分类。

## 实现说明

- 只有一个标签时，走原来的分类路由，加载方式和以前完全一样；多个标签时，用 nhentai 搜索的组合语法（如 `language:chinese tag:"glasses"`）一次请求完成，翻页、排序沿用原有逻辑，会带上全局语言筛选和默认排除，不写搜索历史。
- 2026-11-06 用真实请求验证过：多个标签同时满足、`-tag` 排除、语言组合都生效。比如 `tag:"big breasts"` 240,521 条，加上 `tag:"glasses"` 后是 41,035 条；`x-ray` 和 `x ray` 两种写法结果相同。另外测出 nhentai 不认 `uploaded:<1d` 和 `uploaded:<1y`（结果恒为 0 条），以及短时间请求太多会暂时返回“0 results”，所以标签补全每次只发一个请求。
- 标签补全使用 `POST /api/v2/tags/autocomplete`，不需要登录；失败时只用本地的标签表和翻译表出建议。
- 查询模型的思路参考了 ccbkv/PicaComic 中 fengye39 写的 `NhentaiFilterTerm` / `buildNhentaiCategoryQueryFromParam`，代码按本仓库结构重新实现，另外加了排除和反解析。

## 发布

Android、iOS、macOS 的分发方式和 5.1.5 相同：
- Android 继续使用长期发布签名，应用标识为 `com.github.et3rw.pica_comic`，可以直接覆盖安装 5.1.5；
- iOS 仍是需要自行签名的 unsigned IPA；
- macOS 仍是本地临时签名的通用版 ZIP。

## 发布校验

- Android 工作流执行 103 项回归测试（5.1.5 是 57 项），并检查 APK 的包名、版本和发布证书指纹；iOS、macOS 工作流的检查项和 5.1.5 相同。
- `flutter analyze` 的结果和 5.1.5 逐条一致，没有新增问题。
- 发布前核对下载文件和构建产物的 SHA-256。
- 测试版第 2 版的功能经用户在安卓手机上实际使用确认；iOS 真机安装和桌面端的实际交互仍需用户验证。
