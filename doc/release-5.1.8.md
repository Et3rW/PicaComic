# 5.1.8 发布说明

这一版以维护为主：把项目的依赖和发版流程收拢到自己手里，给所有内置源补上测试，并修掉测试过程中发现的几个问题。新功能只有一个：e-hentai 的标签叠加。版本号 5.1.8（5018）。

## 修复

- **绅士漫画图片全部加载失败**：图片服务器现在要求地址里带校验参数，旧代码把它截掉了，阅读和下载都返回 403。同时修复简介为空、搜索结果里日期和时间粘在一起。
- **禁漫图片在缓存里占两倍空间**：解扰后的图片被写了两遍。这个问题从上游就有。
- **e-hentai**：
  - 账号开启多页查看器（MPV）时图片内容为空；
  - 图片服务器不返回文件大小时，会一直重试到失败。
- **hitomi 和自定义源**：加载进度可能在文件写完之前就报告“完成”，下载漫画时会复制到不完整的文件。现在只有文件写完后才报告完成。
- 自定义源的图片缓存丢失文件类型；源不存在时留下一个“加载中”标记，同一张图要等 15 秒才会重试。

## 新功能

- **e-hentai 点标签叠加搜索**：和 nhentai 的行为一致。在只由标签组成的搜索结果里打开画廊，再点标签，会和原来的标签一起搜索，最多 5 个；新的语言会替换旧的语言。叠加后的搜索在搜索栏下面显示可删除的标签条，单个标签的搜索外观不变。开关在 设置 → 漫画源 → E-Hentai，默认开启。

## 内部改动

- **图片加载**：六个加载函数原来各有一份几乎相同的流程，现在共用一条通道（`ImageManager._load`），各源只描述自己的地址、重试和后处理。
- **依赖**：6 个 git 依赖改为指向 Et3rW 名下的 fork，并锁定到完整提交号（原来指向上游作者的个人仓库，其中一个跟随 `main` 分支）。解析到的代码和 5.1.7 完全相同。
- **发版流程**：版本号只在 `pubspec.yaml` 和 `def.dart` 两处，工作流和 Android 测试版的包名、应用名都从 `pubspec.yaml` 生成；工作流运行 `test/` 下的全部测试。见 [releasing.md](releasing.md)。
- **测试**：从 110 项增加到 185 项，覆盖全部内置源的解析和图片加载；新增每周自动运行的线上检查。见 [source-tests.md](source-tests.md)。

## 已知限制

- 绅士漫画图片地址里的校验参数每次打开都会变，缓存按完整地址记录，所以重新打开同一本漫画会重新下载图片。
- e-hentai 多页查看器的修复只有自动测试覆盖，没有用开启了该功能的账号实际验证。
- 禁漫内置的默认接口域名已经失效，应用启动时会自动获取新的域名，不影响使用。

## 发布校验

- 185 项自动测试通过；`flutter analyze` 比 5.1.7 少一条提示，没有新增。
- 线上检查在本机对 e-hentai、绅士漫画、hitomi、禁漫、nhentai 各完整走了一遍（列表、详情、加载一张图并核对缓存文件），哔咔检查了请求签名。
- 这一版没有经过测试版阶段，发布前没有在真机上使用过；Android 测试包只在 GitHub Actions 上打包并校验了包名和版本。iOS 真机安装和桌面端的实际使用同样没有验证。
